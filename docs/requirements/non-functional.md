# 非機能要件

機能面は [機能要件](functional.md)、全体像は [プロジェクト概要](../overview.md) を参照。対象 OS は Windows のみ。

## 前提と脅威モデル

このアプリは「ネットワーク越しに本人のデスクトップを完全に操作できる入口」であり、侵害されるとホスト上の全権限が奪われる。以下の信頼境界と脅威を前提に要件を定める。

| 境界 / 脅威 | 前提・対策の方向 |
|------------|----------------|
| tailnet 外からの到達 | tailnet IP のみ Listen（FR-A01）。tailnet ACL で到達元デバイスとポートを絞ることを推奨（NFR-S12） |
| tailnet 内の他デバイス・他ユーザー | WhoIs による許可リスト + MCP は Bearer（FR-A03〜A05） |
| 許可済みデバイスのブラウザ上の悪性ページ（CSRF / DNS リバインディング） | Host / Origin 検証、カスタムヘッダー必須（NFR-S02, S03） |
| AI（MCP クライアント・内蔵エージェント）の暴走 | キルスイッチ、承認、オーバーレイ、監査ログ、**自己保護**（NFR-S06）、タスクの上限（FR-G09） |
| プロンプトインジェクション（画面上の文面でエージェントが乗っ取られる） | **決定論的な多層防御**を主体とする: すべてのアクションを InputGuard・リース・キルスイッチ・ルールベースの Judge に通し、API の安全チェックと個別操作はホスト承認に回し、上限と中断で被害を限る（NFR-S15）。エージェントへのプロンプト指示は補助にとどめる。LLM による判定器（Jev 等）を足す場合も、防御の唯一の主体にはせず、承認を求める方向にのみ働かせる（FR-G12） |
| OpenAI API キーの漏えい | Windows 資格情報マネージャーに保管し、ホスト GUI でのみ登録・削除する（NFR-S14） |
| ホストから OpenAI へのデータ送信 | エージェントは既定で無効。有効化時にスクリーンショット送信への同意を記録する（FR-G14、NFR-PR03） |
| ホスト上の他プロセス・他ユーザー | NTFS ACL（NFR-S11）。同一ユーザー権限の悪意あるプロセスは対象外 |
| 更新経路の侵害 | 署名検証（NFR-S10） |

**HTTP のみで提供する（tailnet の WireGuard に暗号化を委ねる）**。このため Web UI は非セキュアコンテキストで動作し、ブラウザの `navigator.clipboard` が使えない（[機能要件 FR-W07](functional.md) は貼り付けイベントと専用入力欄で実現する）。

## 性能（NFR-P）

測定条件: 1920×1080 のシングルモニター、クライアントとホストが tailnet 上で直接経路（DERP 中継でない）、RTT ≤ 30 ms、ホストは 4 コア以上の一般的な CPU。

| ID | 項目 | 目標 |
|----|------|------|
| NFR-P01 | `screenshot` の処理時間（キャプチャ → 縮小 → エンコード。ネットワークを除く） | ≤ 500 ms |
| NFR-P02 | Web UI のライブ表示（10 fps 時）の表示遅延（ホスト画面の変化 → ブラウザ表示） | ≤ 300 ms |
| NFR-P03 | Web UI の入力遅延（ブラウザ入力 → ホストへ注入完了。ネットワークを除く） | ≤ 50 ms |
| NFR-P04 | アイドル時（接続なし or 閲覧者なし）の CPU 使用率 | ≤ 2 %（WebView2 プロセスを除くアプリ本体） |
| NFR-P05 | キルスイッチ発動から全入力停止・全セッション切断まで | ≤ 1 s |
| NFR-P06 | リース取得要求から承認ダイアログ表示まで | ≤ 1 s |
| NFR-P07 | 同時閲覧者 | 最大 5。エンコードは (モニター, 品質, FPS) の組ごとに 1 回だけ行い共有する |
| NFR-P08 | `run_task` / `get_task` / `cancel_task` の応答（`run_task` は `task_id` を返すまで） | ≤ 1 s（ネットワークを除く）。エージェントの 1 ステップの所要時間は OpenAI の応答時間に依存するため目標を置かず、ステップ数と実行時間の上限（FR-G09）で制御する |

メモリ使用量・ネットワーク帯域は初版では目標を置かず、実装後に実測して本書へ追記する。

## セキュリティ（NFR-S）

| ID | 要件 |
|----|------|
| NFR-S01 | tailnet IP 以外のインターフェースでは Listen しない（[FR-A01](functional.md)）。Listen 対象に変化があれば GUI に表示する |
| NFR-S02 | すべての HTTP / WebSocket リクエストで `Host` ヘッダーを検証し、tailnet IP または MagicDNS 名 + 設定ポート以外は拒否する（DNS リバインディング対策）。`Origin` ヘッダーを持つリクエスト（ブラウザ）は、同一オリジンのみ許可する |
| NFR-S03 | Web UI の状態変更 API はカスタムヘッダー（`X-Puppet-Remo: 1`）と `application/json` を必須とし、クロスオリジンのプリフライトを許可しない。MCP は Bearer 必須のため CSRF の対象外 |
| NFR-S04 | Bearer トークンは暗号論的乱数 256 bit、DB にはハッシュ（SHA-256）のみ保存、比較は定数時間。認証失敗は同一デバイスにつき 1 分 10 回までとし、超過は 429 を返して監査ログへ記録する |
| NFR-S05 | WhoIs の結果は接続元 IP 単位に最大 10 秒キャッシュする（IP 再割り当て・ノード削除への追従のため短くする）。WhoIs 失敗時は拒否（fail closed） |
| NFR-S06 | **自己保護**: MCP / Web UI / 内蔵エージェントからの入力注入は、アプリ自身のウィンドウ（ホスト GUI、承認ダイアログ、オーバーレイ）を対象にできない。座標が自ウィンドウ上、またはフォアグラウンドが自プロセスのときは `input_blocked` を返す。自ウィンドウは画面キャプチャから除外する（`WDA_EXCLUDEFROMCAPTURE`）。これにより AI が承認ダイアログを押す、設定を変える、API キーを入力・参照することを防ぐ。内蔵エージェントでは 1 度でもブロックされたらタスクを終了する（FR-G07） |
| NFR-S07 | キルスイッチの発動状態は永続化し、アプリを再起動しても受付停止のまま維持する。解除はホスト GUI での明示操作のみ |
| NFR-S08 | アプリは標準ユーザー権限で動作し、管理者昇格を要求しない（UIPI により管理者ウィンドウは操作不可。[機能要件](functional.md) 参照） |
| NFR-S09 | リソース上限: HTTP ボディ ≤ 1 MiB、`type` のテキスト ≤ 10,000 文字、クリップボード ≤ 1 MiB、WebSocket メッセージ ≤ 64 KiB、`run_task` の `prompt` ≤ 10,000 文字、最終回答 ≤ 10,000 文字。同期の MCP ツール呼び出しのタイムアウトは 30 秒（`run_task` / `get_task` / `cancel_task` は即時に応答するため影響を受けない） |
| NFR-S10 | 自動更新は GitHub Releases から HTTPS で取得し、アプリに埋め込んだ公開鍵（Ed25519）で署名を検証してから適用する。署名検証失敗・ダウングレード（現行より古い版）は適用しない。署名鍵はリリース CI の外に秘匿する |
| NFR-S11 | データ（SQLite、サムネイル、ログ）は `%LOCALAPPDATA%\puppet-remo\` に保存し、NTFS ACL（現在のユーザーのみ）で保護する。**サムネイルは平文**で保存される。残存リスクとして、BitLocker による全体暗号化とサムネイル無効化設定（FR-AU02）を README / 設定画面で案内する。シークレット（OpenAI API キー）はここに置かない（NFR-S14） |
| NFR-S12 | tailnet ACL の推奨ポリシー（接続元を所有者のデバイスに限定し、宛先を本アプリのポートに絞る）を README に記載する |
| NFR-S13 | ログ・監査ログにトークン、クリップボード、`type` 本文を既定で出力しない（[FR-AU03](functional.md)） |
| NFR-S14 | **OpenAI API キー**: Windows 資格情報マネージャー（DPAPI によりユーザーアカウントに束縛）に保管する。SQLite、設定、ログ、監査ログ、クラッシュ出力、GUI の HTML・イベントに**出さない**。入力と削除はホスト GUI のみで、登録後は値を表示しない（登録済みかどうかだけ示す）。`Authorization` ヘッダーはログに出さない。送信先は `api.openai.com` の HTTPS のみ。残存リスク: 同一ユーザー権限の悪意あるプロセスは資格情報マネージャーから読み取れる（脅威モデル外） |
| NFR-S15 | **エージェントの防御は決定論的**: モデルが生成した任意コードをホストで実行する方式（`exec_py` 等）は採らない。`computer` ツールのアクションを 1 件ずつ、MCP 直接・Web UI と同じ入力層（InputGuard → リース → キルスイッチ → Judge → 監査）に通す。承認を省略できる経路を作らない（API の安全チェックは常にホスト承認、Judge の判定は緩める方向に作用させない）。判定の失敗・タイムアウトは承認へ回す（fail-closed） |
| NFR-S16 | OpenAI API の呼び出しは 1 回あたり 60 秒でタイムアウトし、エラー・タイムアウトはタスクを `failed`（`openai_error`）で終了する。同一ステップの自動再試行は行わない。キー無効（401）は GUI に通知してエージェントを無効状態にする |

## 可用性・信頼性（NFR-A）

| ID | 要件 |
|----|------|
| NFR-A01 | リースはメモリ上のみで保持し、再起動で必ず `idle` に戻る。リース保持中にアプリが異常終了しても、接続切断によりオーバーレイとリースは消滅する |
| NFR-A02 | クラッシュ後の自動再起動は行わない（安全側）。次回ログオン時の自動起動（FR-S08）で復帰する |
| NFR-A03 | `tailscaled` の再起動・ネットワーク切替後、10 秒以内に Listen を復旧する（[FR-A02](functional.md)）。復旧中のリクエストは接続拒否となる |
| NFR-A04 | MCP / WebSocket のクライアント切断を検知し（keepalive 15 秒間隔、タイムアウト 45 秒）、当該セッションのリースを解放する |
| NFR-A05 | リース保持中はホストのスリープ・画面消灯を抑止する（`SetThreadExecutionState`）。リース解放で解除する |
| NFR-A06 | SQLite は WAL モードで運用し、起動時に整合性チェックを行う。DB が破損していれば隔離（リネーム）して空 DB で起動し、GUI に通知する |
| NFR-A07 | PC のスリープ・電源オフ中は到達不可（Wake-on-LAN 等は対象外） |
| NFR-A08 | タスクの記録は永続化するが、実行状態はメモリのみで持つ。起動時に、状態が `pending_approval` / `running` のまま残っているタスクを `aborted` に更新する。タスクを自動で再開しない |

## 容量・スケーラビリティ（NFR-C）

個人利用の単一ホストが前提であり、水平スケールは対象外。

| ID | 項目 | 上限 |
|----|------|------|
| NFR-C01 | 登録クライアント数 | 50 |
| NFR-C02 | 同時 MCP セッション | 5 |
| NFR-C03 | 同時 Web 閲覧者 | 5（NFR-P07） |
| NFR-C04 | 監査ログ | 保持期間 30 日・サムネイル 1 GiB（FR-AU04）。件数上限は設けない |
| NFR-C05 | 同時実行のタスク | 1（排他リース。[FR-L08](functional.md)） |

| NFR-CP08 | 内蔵エージェント | ホストが `api.openai.com` へ HTTPS で到達できること。OpenAI の `computer` ツール（GA）に対応するモデルを設定すること（既定 `gpt-6.1-sol`。モデル名は変わりうるため設定で変更可） |

## 運用性・保守性（NFR-O）

| ID | 要件 |
|----|------|
| NFR-O01 | アプリ運用ログ（slog、JSON）を `%LOCALAPPDATA%\puppet-remo\logs\` にローテーション（10 MiB × 5 世代）で出力する。監査ログ（業務記録）とは別物。レベルは設定可 |
| NFR-O02 | 配布は GitHub Releases の NSIS インストーラ（Wails 標準）。更新はアプリ内自動更新（NFR-S10）。更新の適用はホスト GUI の確認後を既定とし、リース保持中・接続中は適用しない |
| NFR-O03 | OS 依存部（画面キャプチャ・入力注入・ウィンドウ列挙・UI Automation・オーバーレイ）はインターフェースの背後に置き、コアロジックは OS 非依存でテスト可能にする（将来の他 OS 対応のため） |
| NFR-O04 | CI は GitHub Actions の `windows-latest` で templ 生成の差分チェック、フロントエンドのビルド、build / vet / lint / test、Lit のテスト、Playwright（偽の platform。[フロントエンド設計](../architecture/frontend.md) §9）を実行する。OS アダプタは実機でのスモークテスト手順を `docs` に記載する |
| NFR-O05 | データベースのスキーマ変更はバージョン付きマイグレーションで管理する |
| NFR-O06 | OpenAI API はインターフェースの背後に置き、CI のテストでは実 API を呼ばない（モックで `computer_call` の連鎖・安全チェック・上限・中断を検証する）。実 API を使うスモークテスト手順は `docs` に記載する |

## プライバシー（NFR-PR）

| ID | 要件 |
|----|------|
| NFR-PR01 | MCP の低レベル `screenshot` の画像は、MCP クライアントが接続している AI サービスへ送られうる。この送信は本アプリの管轄外であり、機密画面を映さない運用（機密ウィンドウの最小化など）は利用者の責任とする。README に明記する |
| NFR-PR02 | 機密ウィンドウの自動マスク・除外は初版の対象外 |
| NFR-PR03 | **内蔵エージェントの送信**: エージェントが有効なときだけ、ホストが OpenAI に送信する。内容は指示、各ステップの縮小スクリーンショット（PNG。プライマリモニターの画面全体）、アクションの履歴（`type` の本文を含む）。画面に映るものはすべて送信されうる。Judge の `deny_processes` は入力のブロックであり、キャプチャのマスクではない（NFR-PR02）。OpenAI 側のデータ保持・学習利用の扱いは OpenAI の規約と API 設定に従い、本書では保証しない。有効化時の同意と日時は監査ログに残す（FR-G14） |

## 未決事項

| 項目 | 内容 |
|------|------|
| Authenticode コード署名 | インストーラ・実行ファイルへのコード署名（SmartScreen 対策）の証明書調達は未定。NFR-S10 の更新署名とは別 |
| メモリ・帯域目標 | 実装後に実測して追記 |
| 判定補助モデル（Jev 等） | エージェントの判定（`Judge`）に外部モデルを使うかは未決。使う場合の送信データ（テキスト・JSON のみか、画像を含めるか）、外部通信先、プライバシー、fail-closed の扱いを本書に追記する。調査では、Jev の画像入力は「Dreamer-ready」（本番基準未満）で、プロンプトインジェクションの検知は公開評価で 74.1%（n=116、信頼区間 0.664〜0.828）にとどまるため、決定論的ルールを主体とする方針は変えない |
| OpenAI 側の保持・学習利用 | `store` の扱い、データ保持期間、学習利用の有無を OpenAI の最新規約で確認して追記する |
| スクリーンショットの送信サイズ | OpenAI が受け付ける画像サイズの上限（パッチ数 30,000 以内、超過すると拒否される）に対し、縮小の最大辺（既定 1568 px）が精度・コストの両面で適切かを実測して調整する |
